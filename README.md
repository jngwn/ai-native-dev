# AI Native Dev

AI 네이티브 개발에서 에이전트에게 일을 오래 맡기기 위한 초기 설계 자료 모음이다.

핵심 관점은 "좋은 코드 작성법"보다 "에이전트가 임의 판단을 줄이고, 검증 가능한 단위로 계속 진행하게 만드는 문서 작성법"이다.

이 저장소는 새 프로젝트에 그대로 넣는 문서 세트가 아니라, 그런 문서 세트를 만들기 위한 템플릿 라이브러리다. 그래서 파일은 복사하기 쉬운 평면 구조로 둔다.

이 저장소는 agent runtime, memory system, tool manager, model gateway, 또는 prompt collection을 만들려는 프로젝트가 아니다.

목표는 어떤 에이전트 도구를 쓰더라도, 프로젝트가 에이전트에게 장기 작업을 맡길 수 있도록 `AGENTS.md`, 설계 문서, 검증 기준, 결정 기록, 인계(handoff) 기준을 세우는 것이다.

즉, 이 저장소의 산출물은 실행 도구가 아니라 프로젝트 운영 문서(project operating docs)다.

| `implementation-plan-template.md` | 큰 기능을 세로 슬라이스와 단계별 완료 기준으로 나누는 템플릿 |

## 사용 방법

이 저장소는 다섯 가지 방식으로 쓴다.

```text
새 프로젝트 시작:
  ai-native-dev -> 새 프로젝트 문서 세트

기존 프로젝트 개선:
  ai-native-dev -> 대상 프로젝트의 문서와 운영 구조

이 저장소 자체 평가:
  repo-review-checklist.md -> ai-native-dev

적용 경험으로 이 저장소 개선:
  대상 프로젝트 적용 결과 -> ai-native-dev

참고 프로젝트로 이 저장소 개선:
  참고 프로젝트 -> ai-native-dev
```

## 새 프로젝트 시작하기

새 프로젝트를 시작할 때는 먼저 `initial-design.md`의 초기 프롬프트를 에이전트에게 준다.

그 다음 `project-documents-template.md`의 최소 문서 세트를 프로젝트에 맞게 채운다. 큰 phase를 micro-slice와 gate로 나눠야 하면 `implementation-plan-template.md`로 `docs/implementation-plan.md`를 확장한 뒤 첫 번째 세로 슬라이스부터 구현한다.

## 기존 프로젝트 개선하기

이미 진행 중인 프로젝트를 개선할 때는 이 저장소의 문서를 그대로 복사하지 않는다.

목표는 대상 프로젝트의 철학, stack, framework, 파일 구조를 존중하면서, 에이전트가 장기 작업을 하다가 실패하기 쉬운 지점만 줄이는 것이다.

처음에는 분석만 요청한다.

```text
<프로젝트 경로>를 ai-native-dev 기준으로 분석해줘.

목표:
- 코드를 고치는 게 아니라, 에이전트가 장기 작업을 더 안전하게 하도록 문서와 운영 구조를 개선하는 거야.
- 대상 프로젝트의 철학, stack, framework, package manager, build tool, 파일 구조를 존중해.
- ai-native-dev 문서를 그대로 복사하지 말고, 필요한 실패 모드만 줄여.
- 새 문서를 만들기 전에 기존 AGENTS.md, README, docs에 넣을 수 있는지 먼저 판단해.
- 반영할 가치가 있는 변경이 없으면 "반영할 변경 없음"이라고 명시해줘.
- 작은 문구 개선이나 새 문서를 억지로 만들지 마.
- 아직 파일 수정은 하지 말고 분석과 제안만 해줘.

결과물:
1. 현재 프로젝트 문서 체계가 잘하는 것
2. 에이전트 실패 모드를 줄이는 데 약한 부분
3. ai-native-dev에서 적용할 수 있는 패턴
4. 반영할 변경 제안
5. 반영하지 않을 변경
6. 사용자 결정이 필요한 항목
7. 반영할 변경이 없다면 그 이유
```

분석 뒤 바로 반영까지 맡기고 싶다면 마지막 줄을 바꾼다.

```text
분석 후, 대상 프로젝트의 철학을 해치지 않는 최소 변경만 직접 반영해줘.
```

## 자체 평가하기

이 저장소 자체를 점검할 때는 `repo-review-checklist.md`를 기준으로 본다.

자체 평가는 문서를 더 늘리기 위한 작업이 아니다. 이 저장소의 문서들이 에이전트 실패 모드를 실제로 줄이는지, 역할이 겹치지 않는지, 완료 기준이 검증 가능한지 확인하는 작업이다.

처음에는 평가만 요청한다.

```text
이 저장소를 repo-review-checklist.md 기준으로 자체 평가해줘.

목표:
- 문서를 더 늘리기 위한 평가가 아니라, 에이전트 실패 모드를 줄이는지 확인하는 평가야.
- 좋은 점, 불명확한 점, 충돌 가능성, 과한 부분, 누락된 부분을 나눠줘.
- 반영할 가치가 있는 변경이 없으면 "반영할 변경 없음"이라고 명시해줘.
- 작은 문구 개선이나 새 문서를 억지로 만들지 마.
- 아직 파일 수정은 하지 말고 평가와 제안만 해줘.

결과물:
1. 현재 문서 체계가 잘하는 것
2. 에이전트 실패 모드를 줄이는 데 약한 부분
3. 문서 간 중복이나 충돌 가능성
4. 반영할 변경 제안
5. 반영하지 않을 변경
6. 반영할 변경이 없다면 그 이유
```

평가 뒤 바로 반영까지 맡기고 싶다면 마지막 줄을 붙인다.

```text
평가 후, 철학을 해치지 않는 최소 변경만 직접 반영해줘.
```

## 적용 경험으로 개선하기

이 저장소의 지침을 다른 프로젝트에 적용한 뒤에는, 그 경험을 다시 이 저장소의 개선 입력으로 쓸 수 있다.

목표는 경험을 모두 기록하는 것이 아니다. 실제 에이전트 작업에서 도움이 된 지침, 과했던 지침, 누락된 지침을 가려내고, 이 저장소의 실패 모드를 줄이는 패턴만 다시 가져오는 것이다.

처음에는 평가만 요청한다.

```text
<프로젝트 경로>에 ai-native-dev를 적용한 경험을 바탕으로 이 저장소를 개선할지 평가해줘.

목표:
- 적용 중 실제로 도움이 된 지침, 과했던 지침, 누락된 지침을 나눠줘.
- 특정 프로젝트 고유 문제를 일반 지침으로 확대하지 마.
- 이 저장소의 에이전트 실패 모드를 줄이는 변경만 제안해.
- 새 문서를 만들기 전에 기존 문서에 넣을 수 있는지 먼저 판단해.
- 반영할 가치가 있는 변경이 없으면 "반영할 변경 없음"이라고 명시해줘.
- 아직 파일 수정은 하지 말고 평가와 제안만 해줘.

결과물:
1. 적용 중 도움이 된 지침
2. 적용 중 과했던 지침
3. 적용 중 누락된 지침
4. 이 저장소에 반영할 변경 제안
5. 반영하지 않을 프로젝트 고유 요소
6. 사용자 결정이 필요한 항목
7. 반영할 변경이 없다면 그 이유
```

평가 뒤 바로 반영까지 맡기고 싶다면 마지막 줄을 붙인다.

```text
평가 후, 이 저장소의 철학을 해치지 않는 최소 변경만 직접 반영해줘.
```

## 참고 프로젝트로 개선하기

다른 프로젝트를 참고해서 이 저장소를 개선할 때는 `reference-analysis-template.md`를 먼저 채운다.

참고 프로젝트는 기술이나 파일 구조를 가져오기 위한 대상이 아니다. 에이전트가 오래 작업하기 좋게 만든 문서 구조, 운영 규칙, 검증 방식, 인계 방식, 결정 기록 방식을 추출하기 위한 대상이다.

처음에는 분석만 요청한다.

```text
<참고 프로젝트 경로>를 참고 프로젝트로 분석해줘.

중요:
- 코드 구현 자체를 분석하지 말고, 설계 문서와 에이전트 운영 문서만 봐줘.
- 목표는 그 프로젝트의 기술 스택(tech stack), framework, package manager, build tool, 파일 구조를 베끼는 것이 아니야.
- AI 에이전트가 장기 개발을 잘 하게 만든 문서 구조, 작업 흐름, 검증(verification) 방식, 인계(handoff) 방식, 결정 기록(decision record) 방식만 추출해줘.
- 이 저장소의 철학을 해치지 않는 개선만 제안해줘.
- 새 문서를 늘리는 제안은 왜 기존 문서에 넣으면 안 되는지까지 설명해줘.
- 반영할 가치가 있는 변경이 없으면 "반영할 변경 없음"이라고 명시해줘. 분석 요청은 변경 요청이 아니야.
- 참고 프로젝트가 좋아 보여도 이 저장소의 에이전트 실패 모드를 줄이지 못하면 반영하지 마.
- 작은 문구 개선이나 새 문서를 억지로 만들지 마.
- 아직 파일 수정은 하지 말고 분석과 개선 제안만 해줘.

먼저 reference-analysis-template.md 형식으로 분석 결과를 작성해라.

그 다음 이 저장소의 문서 중 개선할 가치가 있는 부분만 제안해라.
중복, 장황함, 특정 스택 편향을 만들지 마라.

결과물:
1. 참고 프로젝트에서 배울 수 있는 에이전트 작업 흐름 패턴
2. 이 저장소에 반영할 변경 제안
3. 반영하지 말아야 할 스택 고유 요소
4. 사용자 결정이 필요한 항목
5. 반영할 변경이 없다면 그 이유
```

분석 뒤 바로 반영까지 맡기고 싶다면 마지막 줄을 바꾼다.

```text
분석 후, 이 저장소의 철학을 해치지 않는 최소 변경만 직접 반영해줘.
```
